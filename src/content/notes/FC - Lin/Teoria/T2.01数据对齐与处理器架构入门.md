## 一、对齐与 padding（alineament）【必会】

**规则**：每个字段（camp）都要放在「自身大小的倍数」地址（adreça múltiple de la seva mida）上；不够就补 0 字节（padding）。
**目的**：用一点内存换更快的访问。硬件按对齐好的整块搬运数据，放歪了可能要搬两次。

**算 struct 大小的三步**
1. 从地址 0 开始，按声明顺序放字段。
2. 当前地址不是该字段大小的倍数，就补 0 到下一个倍数。
3. 总大小补到「最大对齐要求」的倍数（末尾 padding）。这样做成数组（array de structs）时，下一个元素也能对齐。

| 声明 | 布局 | 大小 |
| --- | --- | --- |
| `struct { int; char; float; }` | int 0–3，char 4，补 5–7，float 8–11 | 12 |
| `struct { int; int; char; }` | 0–3，4–7，char 8，末尾补 9–11 | 12 |
| `struct { int; double; }` | int 0–3，补 4–7，double 8–15 | 16 |
| `struct { double; int; }` | double 0–7，int 8–11，末尾补 12–15 | 16 |
| `struct { char; int; char; }` | char 0，补 1–3，int 4–7，char 8，末尾补 9–11 | 12 |
| `struct { int; char; char; }` | int 0–3，char 4，char 5，末尾补 6–7 | 8 |

- double 按 8 对齐（课程标准答案在 32 位机器上也这样算）；char 数组按 1 对齐。
- 换字段顺序**不一定**省空间，所有可能的顺序都要算。一般把大的字段放前面更省。
- 编译器会自动补 padding，程序员不用手动处理；可以要求编译器不补，但不推荐。
- 课件原句：«El padding permet que el camp float estigui en una @mem múltiple de la seva mida.»

## 二、union【必会】

- 所有成员都从同一地址开始（la mateixa @ de memòria）；同一时刻只有一个值（un valor a la vegada）；写一个成员会覆盖其他成员（els valors es sobreescriuen）。
- **大小 = 最大成员，再补到最大对齐要求的倍数**。
- `union { int; char[5]; float; }`：最大成员 5 字节，补到 4 的倍数，结果是 8。
- `union { int; char[9]; double; }`：最大成员 9 字节，补到 8 的倍数，结果是 16。
- union 怎么换成员顺序，大小都不变。
- struct 改成 union 后，字段会重叠，写一个字段会改掉另一个，程序行为会变。

| | struct | union |
| --- | --- | --- |
| 成员关系 | 「和」：同时存在 | 「或」：只存一个 |
| 各成员起始地址 | 依次排开 | 全都是 0 |
| 大小 | 各成员之和 + padding | 最大成员 + padding |

## 三、Python 对象（objecte）【看懂】

- 对象是类（classe）的实例，是变量、函数和 struct 的组合；类可以看作 struct 的进化版。
- Python 里每个值都是对象，开头有一段头部（capçaleres）元数据（metadades），内容取决于对象的类型。所以同一个数在 Python 里占的空间比 C 大得多。
- 课程用 C 而不是 Python 来讲原理，是因为对象会加入很多「噪音」，把内存大小和执行过程变成黑箱。

```python
import sys
print(sys.getsizeof(125))   # 64 位 CPython 上一般是 28，远大于 C 的 int（4 字节）
```

## 四、从云到设备【看懂】

- 计算系统（sistema informàtic）= 硬件 + 系统软件，用来执行程序。设备可以完全不同，但概念相同。
- 分层：云（núvol / cloud，数以千计）→ fog / edge（数以百万计，地理上更靠近用户的服务器）→ 终端设备（dispositius，数以十亿计：手表、摄像头、机器人、手机）。
- fog 是 Cisco 提出的概念，后来演化成 edge。

## 五、冯·诺依曼 vs 哈佛【理解】

- **冯·诺依曼**（Arquitectura Von Neumann，最常用）：CPU 从输入设备或内存接收指令和数据，处理后把结果送到输出设备或内存；指令和数据**共用一份存储器**。
- **哈佛**（Arquitectura Harvard）：指令和数据用**分开的存储器**（memòria separada per instruccions i per dades），典型用于 DSP。

| | 冯·诺依曼 | 哈佛 |
| --- | --- | --- |
| 好处 | 便宜、空间分配灵活 | 指令和数据可同时访问 |
| 代价 | 指令和数据挤同一条通路，形成瓶颈（coll d'ampolla） | 线路更多、更贵，容量难以预先分配 |

- 现代 CPU 是混合的：主存只有一份，但 L1 缓存分成 i-cache（指令）和 d-cache（数据）。

## 七、执行一条指令的五个阶段（etapes）【必会】

| 阶段 | 做什么 | 负责部件 |
| --- | --- | --- |
| Fetch | 按 PC 里的地址取下一条指令 | 指令控制单元 |
| Decode | 按 ISA 解码成微操作（microoperacions），并从寄存器堆读出操作数 | 指令控制单元 |
| Execute | 交给功能单元（unitats funcionals：ALU、FPU、Load/Store…）计算 | 执行单元 |
| Memory | 只有 load / store 指令真正访问内存 | 执行单元 |
| Write Back | 按程序顺序写回结果 | Retirement Unit |

- **直接受 ISA 影响的是 Decode**：CISC 越复杂，Decode 越复杂。Fetch 只是间接受影响：CISC 指令长度不固定，取指更麻烦。
- 指令控制单元负责 **Fetch 和 Decode**（真题问过）。
- 为什么要单独 Write Back：可能有很多条指令同时在执行，结果必须按程序顺序写回，所以叫「退休」。
- `C = A + B` 实际是四条指令：load A → load B → add → store C。A、B、C 都在内存里，要先算出地址才能访问。
- `RegA = RegA + RegB` 用到的部件依次是：指令控制单元从 i-cache 取指 → 解码 → 从寄存器堆读出 RegA、RegB → ALU 相加 → 写回 RegA → Retirement Unit 让指令退休。
- 真实处理器会把这五步拆成 15～20 步。

## 八、流水线（pipeline）【理解】

**原理**：像福特的汽车流水线：一个工位做完就把半成品交给下一个，自己马上开始做下一辆车。CPU 里的各阶段也是同时处理不同的指令。

- 不用流水线：总时间 = n × k × t
- 用流水线：总时间 = (k + n − 1) × t_max
- 例：k = 5 个阶段、n = 3 条指令、每段 1 s，不用流水线 15 s，用流水线 7 s。指令很多时，接近每个时钟周期完成一条。

**两个限制**
1. **划分不均匀**（particionat no-uniforme）：性能受限于最慢的那个阶段（l'etapa més lenta）。解决办法是把慢的阶段再拆细，所以现代处理器有 15 级以上（>=15 etapes）。
2. **额外固有成本**（cost inherent addicional）：阶段之间要用流水线寄存器（registres de pipeline）传递结果，它们占芯片面积、也耗电。

> 流水线不会让单条指令变快，变快的是吞吐量（单位时间完成的指令数）。

**看懂即可**：课件 p.9 那张大电路图（类似 RISC-V），PC 和 +4 对应 Fetch，Register File 和 Control Unit 对应 Decode，ALU 对应 Execute，D-Mem 对应 Memory；图中竖着的绿色长条就是流水线寄存器。

## 九、指令集架构 ISA（Conjunt d'Instruccions）【必会】

ISA 规定指令的格式和类型、操作的编码（codificació de les operacions）、访问内存的方式、有哪些寄存器、SIMD 等并行机制。

- 为一种 ISA 编译的程序，在另一种 ISA 的处理器上**无法解码，根本跑不起来**，不是「跑得慢」的问题（例如 x86 vs Arm：Apple M 系列和 Intel Mac）。
- 语义鸿沟（forat semàntic）：ISA 设计要在「更接近高级语言」和「更接近硬件控制信号」之间取舍，这会影响编译器和微架构（microarquitectura）的复杂度。

| | RISC | CISC |
| --- | --- | --- |
| 指令 | 少而简单 | 多而复杂（一条指令可以完成访存 + 计算） |
| 优点 | 降低处理器复杂度 | 降低编译器复杂度 |
| 例子 | ARM、MIPS、RISC-V | 早期 x86、Motorola 68K |

- 后来的 x86 是**混合 CISC-RISC**：对外保持复杂指令以兼容旧软件，芯片内部先翻译成简单的微指令再执行。
- **指令条数少 ≠ 更快**。

**看懂即可**
- 1948 年的曼彻斯特 Baby 是第一台电子存储程序计算机，只用 3 位标识指令（最多 8 种，课件表中列了 7 条）。
- 汇编语言（llenguatge ensamblador）是机器码（codi màquina）的助记符（mnemotècnics）写法：`mov` 搬数，`add` 加，`sub` 减，`jl` 是「小于就跳转」。
- 课件里的机器码例子（教学用的 Y86-64）：`20 10` = `rrmovq %rcx,%rax`，`60 20` = `addq %rdx,%rax`，`72 84 00 00 …` = `jl 0x84`。可以看到指令长度不固定（2 字节或 9 字节），跳转地址按小端序（little-endian）存放。

## 十、寄存器堆与硬件线程【必会】

- **寄存器堆**（Banc de Registres）：存储层次（jerarquia de memòria）中最小、最快的一层，在 CPU 内部；小是因为必须快。
- x86-64 有 **16 个 64 位通用寄存器**（GPR, registres de propòsit general），另外有 52 个子寄存器。
- 寄存器种类：通用寄存器、FPU 寄存器、专用寄存器（program counter、status register）、向量寄存器（registres vectorials）。
- **PC**（program counter）：记录下一条要执行的指令的地址。遇到循环、条件判断、函数调用时会跳到别处。
- 寄存器不够用时，由编译器决定哪些变量放寄存器、哪些暂时放回内存。
- 寄存器堆**不能**用缓存代替：它要直接给指令提供操作数，还承担 PC、标志位等专门用途。
- 处理器**可以**没有缓存：仍能工作，但每次都要访问内存，会慢很多。
- **硬件线程**（Hardware Thread）：硬件提供的执行上下文（context d'execució），核心是寄存器堆。在 Windows 里叫逻辑处理器（processador lògic），也叫 processing unit。

**看懂即可**：子寄存器 RAX（64 位）→ EAX（低 32 位）→ AX（低 16 位）→ AH（第 8–15 位）/ AL（第 0–7 位），它们都是同一个物理寄存器的不同部分。

> 下周会讲（真题年年考）：软件线程与硬件线程、核心（core）、多核 vs 多线程。只有一个寄存器堆时，两个硬件线程不能同时执行。

## 十一、执行单元（Unitats d'Execució）【理解】

| 单元 | 负责（课件原词） |
| --- | --- |
| ALU | nombres enters i lògica binària（整数和二进制逻辑） |
| FPU | coma flotant（浮点） |
| AGU | càlcul de l'adreça per accedir a memòria（计算访存地址） |
| 向量单元（unitats vectorials） | aplicar la mateixa operació a un conjunt de dades（对一组数据做同一种运算） |

ALU 输入两个操作数和一个 4 位 opcode（0000 加、0001 减、1000 AND……，opcode 表不用背），输出结果，并设置四个标志位：

- **C（Carry，进位）**：只对无符号数有意义，表示结果超出范围。
- **V（Overflow，溢出）**：只对有符号数有意义，例如 char 型 127 + 1 = 10000000，此时 C = 0、V = 1。
- **S（Signe，符号）**：结果为负。
- **Z（Zero，零）**：结果为 0。

不同运算的延迟（latència）不同：浮点运算通常比整数运算慢。

## 十二、SIMD（Paral·lelisme SIMD）【必会】

**答题四件套**
1. **是什么**：一条指令处理多份数据（Single Instruction Multiple Data）。
2. **代码哪里能用**：遍历数组连续位置、各次迭代互不依赖的循环。
3. **需要什么硬件**：ISA 里有向量指令（instruccions vectorials），处理器有向量寄存器（registres vectorials）。
4. **效果**：循环迭代次数和执行的指令数变少；如果代码里没有可向量化的部分，指令数可能和原来一样。

| 扩展 | 寄存器 | 位宽 | 能装多少个 float |
| --- | --- | --- | --- |
| SSE | XMM | 128 位 | 4（或 2 个 double） |
| AVX / AVX2 | YMM | 256 位 | 8 |
| AVX-512 | — | 512 位 | 16 |

```c
for (int i = 0; i < 1024; i++)
    c[i] = a[i] + b[i];   // 各次迭代互不依赖，编译器可以自动向量化
```

- 程序员一般不用手写向量指令：给编译器加一个指示（directiva del compilador），编译器会自动向量化。
- 节能：4 次加法只需要取指、解码一次。
- **看懂即可**：Flynn 分类按「指令流 × 数据流」各取单 / 多，分为 SISD、SIMD、MISD、MIMD。
