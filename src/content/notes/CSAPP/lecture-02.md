## 1. 现代计算机的信息存储基石：字节与十六进制编码

*(参考时间：00:02:15 · [视频跳转 (P2 00:02:15)](https://www.bilibili.com/video/BV1iW411d7hd/?p=2&t=135))*

![现代计算机的信息存储基石：字节与十六进制编码 官方讲义图解](</attachments/csapp-397a4d6bef9dcdb21fe165e8.png>)

在孤立的物理层面，计算机芯片内部只有双稳态电路：高电平表示 `1`，低电平表示 `0`。单个比特（Bit）承载的信息量过于贫乏，现代计算机系统一致采用**字节（Byte，8 个比特）**作为**最小的可寻址内存单元**。

一个字节拥有 $2^8 = 256$ 种离散状态：
* 用二进制表示范围为 `00000000_2` 到 `11111111_2`；
* 用十进制表示范围为 $0$ 到 $255$。

但在系统编程和反汇编分析中，二进制太长，十进制无法看清位结构。**十六进制（Hexadecimal，以 16 为基数）**成为行业事实标准：
* 十六进制采用数字 `0`~`9` 以及字母 `A`~`F`（不区分大小写）；
* 每一个十六进制字符恰好精确对应 **4 个二进制比特（称为半字节 Nibble）**；
* 两个十六进制字符恰好紧凑拼装为一个完整的 8 位字节。

| 十六进制字符 | 二进制值 (Nibble) | 十进制值 | 十六进制字符 | 二进制值 (Nibble) | 十进制值 |
|:---:|:---:|:---:|:---:|:---:|:---:|
| `0` | `0000` | 0 | `8` | `1000` | 8 |
| `1` | `0001` | 1 | `9` | `1001` | 9 |
| `2` | `0010` | 2 | `A` | `1010` | 10 |
| `3` | `0011` | 3 | `B` | `1011` | 11 |
| `4` | `0100` | 4 | `C` | `1100` | 12 |
| `5` | `0101` | 5 | `D` | `1101` | 13 |
| `6` | `0110` | 6 | `E` | `1110` | 14 |
| `7` | `0111` | 7 | `F` | `1111` | 15 |

> **极速心算法则**：
> 记忆 `0xA` (`10`), `0xC` (`12`), `0xF` (`15`)。
> 当看到十六进制数 `0x5C` 时，瞬间拆解：`5` 是 `0101`，`C` 是 `1100`，拼成完整字节即 `01011100`，十进制为 $5 \times 16 + 12 = 92$。

## 2. 常见 C 数据类型在 32 位与 64 位机器中的字长对比

*(参考时间：00:09:40 · [视频跳转 (P2 00:09:40)](https://www.bilibili.com/video/BV1iW411d7hd/?p=2&t=580))*

![常见 C 数据类型在 32 位与 64 位机器中的字长对比 官方讲义图解](</attachments/csapp-cc0772411467a17e28ca9050.png>)

机器的“字长（Word Size）”由 CPU 通用寄存器和虚拟内存寻址指针的宽度决定。
从 32 位机器演进到 64 位 x86-64 架构，数据类型的物理宽度发生了关键分化：

| C 数据类型 | 典型 32 位系统 (IA32) | 典型 64 位系统 (x86-64 / LP64) | 汇编操作码后缀 |
|:---|:---:|:---:|:---:|
| `char` | 1 字节 (8 位) | 1 字节 (8 位) | `b` (byte) |
| `short` | 2 字节 (16 位) | 2 字节 (16 位) | `w` (word) |
| `int` | 4 字节 (32 位) | 4 字节 (32 位) | `l` (long word) |
| `long` | **4 字节 (32 位)** | **8 字节 (64 位)** | `q` (quad word) |
| `long long` | 8 字节 (64 位) | 8 字节 (64 位) | `q` (quad word) |
| **指针类型 (`char*`, `void*`)** | **4 字节 (32 位)** | **8 字节 (64 位)** | `q` (quad word) |
| `float` | 4 字节 (32 位) | 4 字节 (32 位) | `s` (single) |
| `double` | 8 字节 (64 位) | 8 字节 (64 位) | `l` (double precision) |

> **关键架构差异**：
> 在 32 位系统下，指针只有 4 字节，整个进程的最大虚拟地址空间上限被死死锁在 $2^{32} = 4\text{GB}$；
> 在 64 位系统下，指针扩充为 8 字节，理论虚拟寻址能力达到 $2^{64} = 16\text{EB}$（Exabytes），这也是为什么现代大型数据库与服务器全面普及 64 位架构的原因。

## 3. 布尔代数体系与位向量 (Boolean Algebra & Bit Vectors)

*(参考时间：00:18:10 · [视频跳转 (P2 00:18:10)](https://www.bilibili.com/video/BV1iW411d7hd/?p=2&t=1090))*

![布尔代数体系与位向量 (Boolean Algebra & Bit Vectors) 官方讲义图解](</attachments/csapp-df635eeb206f5b8b8af6d079.png>)

19 世纪中叶，数学家 George Boole 创立了**布尔代数**。在由 $\{0, 1\}$ 构成的系统上定义了四种基础运算：
* **与 (AND, $\&$)**：全 1 才是 1（$1 \& 1 = 1$, 否则为 0）；
* **或 (OR, $\mid$)**：有 1 就是 1（$0 \mid 0 = 0$, 否则为 1）；
* **非 (NOT, $\sim$)**：反转比特（$\sim 1 = 0, \sim 0 = 1$）；
* **异或 (XOR, $\oplus$ 或 `^`)**：不同才为 1，相同则为 0（$1 \oplus 0 = 1, 1 \oplus 1 = 0, 0 \oplus 0 = 0$）。

当我们将布尔运算扩展到长度为 $w$ 的**位向量（Bit Vectors）**时，它展现出了惊人的数学同构性：
位向量可以直接用于**高效紧凑地表示数学集合（Set Representation）**！
* 假设我们用一个 8 位向量编码集合 $\{0, 1, 2, 3, 4, 5, 6, 7\}$ 的子集：
  * 若第 $i$ 位是 1，表示数字 $i$ 属于该集合。
  * 向量 `01100010` 代表集合 $\{1, 5, 6\}$；
  * 向量 `01010100` 代表集合 $\{2, 4, 6\}$；
* 此时：
  * **按位与 `&`** 对应集合的**交集（Intersection）**：`01000000` $\to \{6\}$；
  * **按位或 `|`** 对应集合的**并集（Union）**：`01110110` $\to \{1, 2, 4, 5, 6\}$；
  * **按位非 `~`** 对应集合的**补集（Complement）**；
  * **按位异或 `^`** 对应集合的**对称差（Symmetric Difference）**。
这一技巧在操作系统位图管理（Bitmap Allocation）与高并发布隆过滤器中广泛使用。

## 4. C 语言中的位级运算 vs 逻辑运算的深水区

*(参考时间：00:27:50 · [视频跳转 (P2 00:27:50)](https://www.bilibili.com/video/BV1iW411d7hd/?p=2&t=1670))*

![C 语言中的位级运算 vs 逻辑运算的深水区 官方讲义图解](</attachments/csapp-7e9ee91664799eb1a1c2e8f9.png>)

C 语言严格区分了两组符号体系，混淆它们是初学者最为致命的语法灾难：
1. **位级运算符（`&`, `|`, `~`, `^`）**：
   逐个比特位独立并行计算，无论操作数的值是什么，都原原本本按照位模式进行门运算。
   ```c
   unsigned char a = 0x69; // 01101001
   unsigned char b = 0x55; // 01010101
   a & b; // 01000001 (0x41)
   a | b; // 01111101 (0x7D)
   ~a;    // 10010110 (0x96)
   ```

2. **逻辑运算符（`&&`, `||`, `!`）**：
   只关心操作数整体是“真（非零）”还是“假（零）”，运算结果永远被归一化为纯粹的 `1` 或 `0`。
   ```c
   !0x41   == 0; // 非零值的逻辑非是 0
   !0x00   == 1; // 零值的逻辑非是 1
   !!0x41  == 1; // 双重逻辑非将任意非零值转换为标准布尔 1
   0x69 && 0x55 == 1; // 两个非零值相与，结果是 1
   ```

> **短路求值特性（Short-Circuit Evaluation）**：
> 逻辑运算符从左到右执行。若第一个操作数已经能够决定义理结果，后续表达式**绝对不会被执行**！
> ```c
> if (p != NULL && *p > 0) { ... }
> ```
> 这一经典防御性代码完全依赖短路求值。如果误写成按位与 `if (p != NULL & *p > 0)`，则无论 `p` 是否为空指针，右侧的 `*p` 都会被强行解引用，瞬间引发段错误导致程序崩溃！

## 5. 移位运算深度辨析：逻辑右移 vs 算术右移与未定义行为

*(参考时间：00:38:20 · [视频跳转 (P2 00:38:20)](https://www.bilibili.com/video/BV1iW411d7hd/?p=2&t=2300))*

![移位运算深度辨析：逻辑右移 vs 算术右移与未定义行为 官方讲义图解](</attachments/csapp-6bef512916518d195b03feee.png>)

位移运算将二进制位按指定偏移量 $k$ 整体滑动：
* **左移运算 `x << k`**：
  所有位向左平移 $k$ 位，丢弃溢出最高位的 $k$ 个比特，并在低位右侧补填 $k$ 个 `0`。左移 $k$ 位等价于乘以 $2^k$。
* **右移运算 `x >> k`** 存在完全不同的两种硬件策略：
  1. **逻辑右移（Logical Shift）**：左侧最高位空出的位置全部**补填 `0`**。
  2. **算术右移（Arithmetic Shift）**：左侧最高位空出的位置全部**复制原符号位（Sign Bit Extension）**！若原数最高位是 1，则全补 1；若最高位是 0，则全补 0。

```text
原始 8 位向量 x: [ 1 1 0 0 0 1 0 0 ]  (最高位是 1，有符号负数)

逻辑右移 2 位:   [ 0 0 1 1 0 0 0 1 ]  (填 0，无符号数 0x31)
算术右移 2 位:   [ 1 1 1 1 0 0 0 1 ]  (填 1，保持负号 0xF1)
```

> **C 语言标准未定义行为陷阱（Undefined Behavior, UB）**：
> 1. 对于**无符号数**，C 标准强制规定右移必须采用**逻辑右移**；
> 2. 对于**有符号数**，几乎所有现代编译器（GCC、Clang、MSVC）都默认采用**算术右移**；
> 3. **移位量越界**：如果一个整型位宽是 $w$ 位（如 32 位），执行 `x << 32` 或 `x << -1`，在 C 标准中属于**未定义行为（UB）**！在 x86-64 硬件层面，CPU 只会取移位量的低 5 位（即 `k % 32`），执行 `x << 32` 实际上相当于 `x << 0`，原本以为清空的变量分毫不变！

## 6. 整数编码体系数学推导：无符号数 B2U 与有符号补码 B2T

*(参考时间：00:49:10 · [视频跳转 (P2 00:49:10)](https://www.bilibili.com/video/BV1iW411d7hd/?p=2&t=2950))*

![整数编码体系数学推导：无符号数 B2U 与有符号补码 B2T 官方讲义图解](</attachments/csapp-12ae8a8b09d1859c4ed1f0b7.png>)

对于一个位宽为 $w$ 的二进制位向量 $\vec{x} = [x_{w-1}, x_{w-2}, \dots, x_0]$：

#### 1. 无符号编码 (Binary to Unsigned, B2U)
每个位都赋予正的权值 $2^i$：
$$B2U_w(\vec{x}) = \sum_{i=0}^{w-1} x_i 2^i$$
* 最小值（全 0）：$UMin = 0$
* 最大值（全 1）：$UMax = \sum_{i=0}^{w-1} 2^i = 2^w - 1$
* 对于 32 位无符号数：$UMax = 2^{32} - 1 = 4,294,967,295$。

#### 2. 补码编码 (Binary to Two's Complement, B2T)
补码最精妙的发明，就是将最高有效位 $x_{w-1}$ 称为**符号位（Sign Bit）**，并赋予它**负权重** $-2^{w-1}$：
$$B2T_w(\vec{x}) = -x_{w-1} 2^{w-1} + \sum_{i=0}^{w-2} x_i 2^i$$

* **最小值 $TMin$**（最高位为 1，其余全为 0）：
  $$\vec{x} = [1, 0, 0, \dots, 0] \implies TMin_w = -2^{w-1}$$
  （对于 32 位系统，$TMin = -2^{31} = -2,147,483,648$）
* **最大值 $TMax$**（最高位为 0，其余全为 1）：
  $$\vec{x} = [0, 1, 1, \dots, 1] \implies TMax_w = \sum_{i=0}^{w-2} 2^i = 2^{w-1} - 1$$
  （对于 32 位系统，$TMax = 2^{31} - 1 = 2,147,483,647$）
* **数值 `-1` 的位模式**（全 1）：
  $$\vec{x} = [1, 1, 1, \dots, 1] \implies -2^{w-1} + (2^{w-1} - 1) = -1$$

#### 补码的核心数学性质与不对称性
1. **$|TMin| = TMax + 1$**：负数范围比正数绝对值大 1！因为 `0` 占用了正数区间的全 0 编码。
2. **反转求负数的高速位级公式**：
   对任何补码数 $x$，其相反数 $-x$ 可以通过**全部按位取反再加 1** 极速得出：
   $$-x = \sim x + 1$$
   *证明*：因为 $x + \sim x = [1, 1, \dots, 1] = -1$，所以 $\sim x = -x - 1 \implies -x = \sim x + 1$。
