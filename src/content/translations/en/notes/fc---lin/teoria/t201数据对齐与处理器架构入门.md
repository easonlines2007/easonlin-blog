## One, alignment with padding (alineament) and the other will be matched

**rules**: Each field (camp) must be placed on the "multiple of its size" address (adreça múltiple de la seva mida); it is not enough to add 0 bytes (padding). 
**Purpose** A bit of memory: replacing faster access. The hardware moves the entire data in a neat way, distorting the probability of moving twice.

**Three steps of struct size**
1. Starting with address 0, field in the order declared.
2. The current address is not a multiple of the field size, but a multiple of 0 to the next one.
3. The total size is added to the multiples of "maximum alignment requirements" (end padding).

| Declaration | The layout | Size |
| --- | --- | --- |
| `struct { int; char; float; }` | In the case of int 0 ⁇ 3, char 4, supplement 5 ⁇ 7, float 8 ⁇ 11 | 12 |
| `struct { int; int; char; }` | 0x3, 4x7, char 8, ending with 9x11 | 12 |
| `struct { int; double; }` | Int 0 to 3, add 4 to 7, double 8 to 15 | 16 |
| `struct { double; int; }` | Double 0 to 7, int 8 to 11, end to 12 to 15. | 16 |
| `struct { char; int; char; }` | Char 0, supplement 1 to 3, int 4 to 7, char 8, end of supplement 9 to 11. | 12 |
| `struct { int; char; char; }` | int 0 ⁇ 3, char 4, char 5, ending with 6 ⁇ 7 | 8 |

- Double is aligned with 8 (the standard answer to the course is also calculated on 32-bit machines); char is aligned by 1.
- Change the field order **Not necessarily.** Save space, all possible sequences are calculated. Generally, the large fields are saved in front.
- The compilation machine automatically fills the padding, without manual processing by programmers; it can be requested that the compilation device not be filled, but not recommended.

## Two, the union will be broken.

- All members start at the same address (la stessa @ de memoria); there is only one value (un valor a la vez) at the same time; writing one member will cover all other members (els valores es sobreescriuen).
- **Size = largest member, then multiply by the maximum alignment requirement**.
- `union { int; char[5]; float; }` The largest member is 5 bytes, plus 4 times the result is 8.
- `union { int; char[9]; double; }` The largest member is 9 bytes, plus the multiple of 8 and the result is 16.
- The union has changed in size and order.
- After struct is changed to union, fields overlap, writing one field changes another and the behavior of the program changes.
